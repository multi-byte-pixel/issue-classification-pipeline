# Starter status and acceptance boundaries

This first slice is implemented on a review branch. No AWS resources have been provisioned and no paid inference has been executed as part of creating it.

## Implemented

- **Offline path:** locked Python dependencies, typed contracts, provider abstraction, deterministic fake, local CLI, fail-closed gates, JSON/Markdown/CSV/JUnit reports.
- **Synthetic evaluation:** seeded template coverage, ambiguity, multi-issue text, adversarial text, and paired multi-turn clarification/correction scenarios. Ground truth is never passed into the classifier.
- **Cloud boundary:** injectable Bedrock adapter, IAM-signed HTTPS runner, HTTP error distinctions, structured logs without raw input, bounded retries/timeouts.
- **Infrastructure baseline:** statically validated dev Terraform for authenticated API Gateway, Lambda, runtime-role boundary, scoped inference policy, logs, error alarm, encrypted/private/versioned artifacts bucket and retention.
- **Delivery:** pinned actions, credential-free CI, static infrastructure validation, manual main-only cloud-opt-in dev workflow, health check, manual evaluation, and teardown that always refuses destruction.

## Verification scope

Local verification covers lint, formatting, strict type checks, unit/contract/evaluation tests, deliberate failing gates, deterministic generation, report parsing, reproducible Linux packaging, and Terraform validation without a backend. The live integration test is skipped by default.

See the [local verification record](verification.md) for commands and observed scope. GitHub Actions check results belong to the starter PR and are the authoritative hosted-CI evidence; passing checks do not validate AWS IAM, model access, deployed latency, or classification generalization.

## Deliberately deferred

| Item | Boundary / next acceptance criterion |
|---|---|
| Bootstrap IAM and state | Reviewed account-admin prerequisite, not broad autogenerated permissions |
| AWS deployment | Approved account/model, backend, boundary, roles, protected environment, spend controls, reviewed plan, real smoke test |
| Production | No deployable prod stack; operational/security/quality approval required |
| Model-quality claims | Real-model reviewed dataset and sufficient independent coverage |
| S3 report upload | Bucket exists in design; writer implementation and role tests deferred |
| Baseline regression | Compatible model/prompt/dataset/config comparison not implemented |
| Semantic evaluators / generated data | No judge or generator LLM until provenance/review controls exist |
| Human-review queue | `NEEDS_REVIEW` response only; no actual queue, ownership, or SLA |
| Confidence / detailed reasons | Confidence omitted; initial reasons are timeout, provider error, invalid output, ambiguity |
| Ephemeral destroy | No isolated ephemeral state, so destruction fails closed |
| Reusable Terraform modules | One transparent dev stack first; factor after verified deployment |
| More observability | Alarm routing, latency/throttle alarms, tracing, dashboards, cost alerts, SLOs |
| Supply-chain hardening | Vulnerability policy, SBOM, signatures, immutable plan promotion |
| Coverage expansion | Typos, malformed-input generation, mutations, fixture files, richer taxonomies |
| Operations | Drift detection, rollback, load tests, idempotency, security review |

The original Phoenix prompt remains intact. This implementation makes deliberate smaller-slice choices instead of marking every requested TODO as complete.
